# 01. El Mindset del Desarrollador UX: UX vs. UI y Fundamentos

## 1. Fundamentación Teórica (Hassan Montero)
* **Experiencia de Usuario (UX) vs. Marketing:** Si el marketing tradicional se basa en promesas, la UX se basa en hechos. La aceptación social y competitiva de un producto depende de su capacidad para resolver necesidades de forma fluida y eficiente[cite: 6].
* **La Interfaz de Usuario (UI) como Espacio de Encuentro:** Es el punto de contacto físico/digital a través del cual el usuario y el sistema interactúan[cite: 6].
* **El Ecosistema Disciplinar:** La UX integra raíces históricas de la Interacción Persona-Ordenador (HCI), la Ingeniería de la Usabilidad (enfoque pragmático coste-beneficio y ROI), el Diseño de Interacción y la Arquitectura de Información[cite: 6, 7].
* **Relación Usabilidad - Utilidad:** La utilidad es el valor intrínseco (si resuelve el problema); la usabilidad es el grado en que el usuario puede explotar dicha utilidad sin frustración[cite: 11, 34].

## 2. Enfoque y Criterio de la Cátedra (Clase 1 del Profesor)
* **El código no vive en el vacío:** El éxito de un sistema depende de quién lo usa. Si el usuario no comprende el flujo o no logra loguearse, para él el sistema falla, sin importar la calidad técnica del backend[cite: 141].
* **Diferenciación conceptual:**
  * **UX (El Sentimiento / El Porqué y Cómo):** Lo que experimenta la persona (frustración, agilidad, confianza)[cite: 141]. Análogo a la arquitectura del sistema y lógica de negocio[cite: 141].
  * **UI (El Medio / Lo Visible):** Controles, layout, tipografía, paleta cromática[cite: 141]. Análogo a la capa de presentación (CSS / Frontend)[cite: 141].
* **Los 5 Pilares Prácticos:**
  1. *Usabilidad:* Facilidad para completar tareas[cite: 141].
  2. *Accesibilidad:* Inclusión de usuarios con limitaciones motrices o visuales[cite: 141].
  3. *Utilidad:* Relevancia funcional real para el usuario[cite: 141].
  4. *Desempeño:* Velocidad de respuesta (latencias excesivas destruyen la UX)[cite: 141].
  5. *Emoción:* Percepción de seguridad y confianza visual[cite: 141].
* **Impacto para el Desarrollador:** Diseñar con foco UX reduce bugs lógicos, minimiza retrabajo/refactorización y reduce drásticamente tickets de soporte[cite: 141].

## 3. Directrices de Implementación Técnica en el Proyecto
* **Separación de Capas:** Mantener coherencia estricta entre la interacción esperada y la respuesta visual del componente (evitar desfases entre lógica y feedback).
* **Eficiencia en Formularios y Cargas Críticas:**
  * No sobrecargar de campos innecesarios los formularios de entrada[cite: 47, 141].
  * Implementar estados de carga (*loading spinners*, barras o esqueletos) para que el rendimiento percibido sea óptimo y no genere incertidumbre de bloqueo[cite: 99, 141].
  * Validar entradas en tiempo real o con mensajes contextuales claros sin culpar al usuario[cite: 49, 54].
* **Ergonomía de Interacción:** 
  * Separar visual y espacialmente acciones destructivas de acciones primarias (ej. botón "Eliminar" distanciado y diferenciado de "Guardar" para prevenir errores accidentales)[cite: 53].
  * Asegurar tamaños mínimos cliqueables/tocables para elementos accionables siguiendo patrones interactivos estándar[cite: 48, 84].

## 4. Trazabilidad para la Entrega y Defensa (Documento + Presentación)
* **Para el Documento de Investigación (Parte 1 de la Consigna):**
  * Incluir la definición del *Mindset UX*: cómo se pensó la solución desde la perspectiva del usuario final y no desde la comodidad del desarrollador[cite: 30, 141].
  * En la sección de *Valor Agregado*, justificar por qué la arquitectura interactiva y la simplicidad de la app superan a las alternativas gratuitas existentes (reducción de fricción, velocidad y claridad)[cite: 1, 141].
* **Para la Presentación / Demo (Parte 2 de la Consigna):**
  * **Diapositiva / Demostración en vivo:** Presentar un caso de uso concreto (ej. flujo de registro, reserva o compra) contrastando el estado "crudo/confuso" vs. la interfaz final optimizada[cite: 141].
  * **Argumento oral para el tribunal:** *"Aplicamos el principio de que la UI es solo el medio para desencadenar una UX eficiente[cite: 141]. Diseñamos este flujo minimizando clicks y tiempo de respuesta para garantizar una experiencia sin fricción cognitiva[cite: 47, 141]"*.
